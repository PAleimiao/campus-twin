# 云函数与云数据库部署说明（campus-twin 后端 · 备选方案）

> ## ⚠️ 先看这里：现在默认不用这套
>
> 仓库里已经有一份**零依赖的本地后端** `local-server/`，双击 `启动本地服务.bat` 就能在电脑上跑，
> **不用开通云环境、不用上传部署**。两端 `config.js` 里的 `backend: 'local'` 指的就是它。
>
> 两套后端的接口**完全同名**（`login / changePassword / getNews / manageNews / importStudents / seedOrg`），
> 入参出参也一致，所以切换只改 `config.js` 里那一个值：
>
> | 想跑哪个 | 怎么切 |
> | -------- | ------ |
> | 本地 Node 服务（默认，推荐） | `backend: 'local'`，然后照 `local-server/README.md` 启动 |
> | 微信云开发 | `backend: 'cloud'` 并填好 `cloudEnv`，再照本文件把 6 个云函数部署一遍 |
>
> 下面的内容只在 `backend: 'cloud'` 时才需要看。

---

> 本目录是「学生端 + 教师端」双小程序共享的后端，全部跑在**微信云开发 CloudBase** 上。
> 设计原则：密钥/密码**只在云函数内处理**，前端永远拿不到明文密码和哈希。

---

## 一、目录结构

```
cloud/functions/
├── login/          账号密码登录（学生/教师通用）
├── changePassword/ 修改密码（唯一不受“强制改密”拦截的接口）
├── importStudents/ 教师批量导入学生（默认密码 123456，强制改密）
├── seedOrg/        组织树一次性初始化（届/学院/专业/班级 + demo 教师/学生）
├── getNews/        读取校园资讯（学生端首页，公开可读）
└── manageNews/     校园资讯管理（教师端远程增删轮播图/资讯，需教师登录）
```

每个函数目录里都有三件套：
- `index.js` —— 业务逻辑
- `lib.js`   —— 公共库（scrypt 加盐哈希、登录态校验 `auth`、数据库入口），**四个函数各放一份**，
               因为微信云开发每个云函数独立部署，右键「上传并部署」只打包当前文件夹。
- `package.json` —— 依赖 `wx-server-sdk`

| `scores`        | 成绩（后续模块）             | —        |
| `checkinSessions` | 签到会话（后续模块）       | —        |
| `attendance`    | 考勤/旷课记录（后续模块）     | —        |
| `books`         | 图书（后续模块）             | —        |
| `borrows`       | 借阅流水（后续模块）         | —        |
| `qualifications`| 学生资质/证书（后续模块）     | —        |

> 目前实际用到：`teachers / students / sessions / news`（+ 组织树的 `grades / colleges / majors / classes`）。
> 其余集合是 v1.1 扩展模块用的，提前建好不碍事，也可以等做到对应模块再建。
> **`news` 集合** 记录格式：`{ type:'banner'|'article', title, date, image, order, createdAt }`，
> 由教师端「校园资讯」管理页远程维护；学生端 `getNews` 读取，读不到时用本地预设图兜底。

**权限设置**：所有集合的「权限设置」建议选 **“仅创建者可读写”** 或 **“所有用户不可读写，仅通过云函数访问”**——
本系统全部走云函数，前端不直接连库，所以选后者最安全（云函数以管理员身份读写）。

## 三、部署步骤（开发者工具里操作）

1. 用微信开发者工具打开 `student-end/`（学生端）或 `teacher-end/`（教师端）任意一个，
   首次会提示「开通云开发」，按向导建一个**云开发环境**，记下**环境 ID**。
2. 把环境 ID 填进两端小程序的 `app.js` 里的 `cloud.init({ env: '你的环境ID' })`。
3. 在 `cloud/functions/` 下，**对每个函数文件夹**右键 →
   **「上传并部署：云端安装依赖」**（会自动 `npm install wx-server-sdk`）。
   四个函数都要传一遍。
4. 部署完成后，先调一次 `seedOrg` 初始化演示数据：
   - 在 `seedOrg` 文件夹右键 →「上传并部署」后，
   - 右键该函数 →「本地调试」或在云函数列表里「测试」，
   - 传入参数 `{ "key": "CAMPUS_SEED_2026" }`，点运行。
   - 成功后会返回 demo 教师/学生账号（见下方）。

> ⚠️ `seedOrg/index.js` 顶部的 `SEED_KEY` 默认是 `CAMPUS_SEED_2026`，正式用请改成你们自己的口令。

## 五、安全要点（对应设计文档 §七）

1. **密码绝不明文**：用 Node 内置 `crypto.scrypt` 加盐哈希存储（`lib.js`）。
2. **强制改密服务端拦截**：`auth(token)` 在 `mustChangePwd=true` 时，除 `changePassword` 外一律返回
   `FORCE_PWD_CHANGE` —— 即使换客户端也绕不过。
3. **防爆破**：登录连续错 5 次锁 10 分钟（`login/index.js` 的 `MAX_FAIL` / `LOCK_MS`）。
4. **改密即失效**：`changePassword` 成功后删除该用户所有 `sessions`，必须重新登录。
5. **导入健壮**：学号格式校验、姓名/班级必填、重复学号更新而非新增、单次上限 200 条。
